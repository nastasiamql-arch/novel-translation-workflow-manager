# Palantir: Novel v3.12.0

Fixes Translator export reminders after restart and copies the latest editor content safely across vocabulary, translation, custom, multiple-step, normal-file and ZIP actions.

Polish History now uses compact rows and permanent per-novel numbers. The trash button immediately moves only the selected snapshot to Windows Recycle Bin. If recycling is unavailable, the operation fails without permanent deletion. Existing direct clipboard references block deletion; new history clipboard copies remain available independently of their snapshot.

History numbers are reserved atomically in each profile's `history_numbers.json`, retained after deletion and migrated from creation time plus stable snapshot ID. Number migration does not rename folders or change payload bytes/hashes.

Display-only normalization does not save untouched files during COPY STEP. Actual unsaved edits are saved with their existing UTF-8 BOM and newline convention; external edit conflicts preserve the source, recovery data and previous clipboard. Copied files are frozen in the existing persistent application clipboard cache. Identical filenames remain separate attachment paths.

The existing export sequence remains: confirm, snapshot configured review attachments, verify snapshot, export TXT, update Context. History copies use historical bytes exclusively. Installer identity and `%LOCALAPPDATA%/NovelWorkflow` stay unchanged.

Windows CI validates the full test suite, native clipboard, DPI layouts, native Recycle Bin, packaged recycle dependencies, installation over v3.11.1, published updater discovery and the downloaded installer.
